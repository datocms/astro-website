# PLAN: port the redesign from the prototype

The source is the prototype at `../../prototype` (repository `datocms/website-prototype`, commit `47d6f26` when this plan started). Its rules are in its `AGENTS.md`, `src/data/AGENTS.md`, `src/scenes/AGENTS.md`, and its page list is in `INVENTORY.md`. Read them before you port a page.

## Branch

- All the work is on the long-lived branch `redesign`. Nothing goes to `main` until the marketing set is complete.
- Each step below is one commit (or a few) on `redesign`. A step that fails its checks is not committed.
- Rebase `redesign` on `main` from time to time. A port adds new files and deletes old ones, thus conflicts are rare.
- Do not push and do not deploy without the approval of a human. The review deploy is `staging2`, by hand.

## Principles

1. **(Ended 2026-10-30.)** The prototype is no longer the source: all new work happens in this repo. The port stopped at prototype commit `47d6f26252160a847d3fef2b483bbf646a8d5844` (2026-10-30, "Developers: new copy"); to port a later change of the prototype, diff from that commit. The old rule was: **The prototype paths stay the same.** A component, a data file or a scene has the same path here as in the prototype. Then a later change in the prototype is a copy of a directory. To get this, the old components with the same name (case-insensitive: macOS does not see a difference) get the prefix `Legacy`.
2. **Two layout families, never mixed on one page.** An old page uses `LegacyLayout` (and the old `global.css`). A new page uses `src/layouts/Layout.astro` (and `src/styles/global.css`). The two stylesheets never load on the same page.
3. **The head of the site stays.** The new layout uses `BaseLayout` for the head: the SEO tags, the favicon, the canonical URL, the RSS links, the cookie consent, the analytics, the draft-mode content link.
4. **The SEO stays editable.** When the old page has a CMS record with `seo` / `_seoMetaTags`, the new page still queries it. When it has none, the page builds the tags from a title and a description.
5. **The CMS queries use the query runner of the site** (`executeQuery(Astro, query)`): draft mode, surrogate keys, content link. Fragments and `_graphql.ts` files port unchanged.
6. **A ported route removes the old one.** Delete the old page folder, add its redirects to `astro.config.ts`, and change the links that point to it.
7. **Copy code, not Figma notes.** When you copy a file from the prototype, remove the comments that refer to Figma (frames, node IDs, variants) and the comments that only say what the code says. Keep a comment only when it tells something that the code does not make clear.

## Checks for every step

```bash
npx astro check            # no new errors
npm run lint:css           # after step 2
npm run build              # must pass
```

Do not run `astro build` or `astro check` while `astro dev` runs (they break the dev cache). For a page port, also start `npm run dev`, get the page with `curl -sf`, and compare it with the prototype (`npm run dev` there, on another port) at 1320 px and 393 px with `agent-browser`, in light and dark.

### 3 to 13. Page ports

**Before the port: a review with a human.** The new page can miss things that must stay. Thus, before an agent ports a route, the main session compares the old page and the prototype page (sections, copy, data sources, links, structured data, client behaviour) and asks the human about each difference: remove it, or adapt / augment the new components to keep it. The answers go in the note of the step below. The port agent follows them and deletes nothing else that the review did not cover. If it finds a new difference, it keeps the old behaviour and writes it in the log.

The routine for each route:

1. Copy the page folder of the prototype (`src/pages/<route>/`), and any `_graphql.ts` or `_style.module.css` in it.
2. Copy the components, scenes and data that it needs and that changed in the prototype after step 2.
   - **Images.** The prototype `public/images/` is not copied as a whole: many of its images are examples of content that the CMS already has (the team, the case studies, the reviews of the wall of love, the customer logos, the blog). When the CMS has the data, the page reads it from the CMS and the images are not copied. Copy into `public/images/` only the static images of the design that have no source in the CMS.
   - **Scope of the layers.** Add the page directory (or file) under `src/pages/` to `REDESIGN_PAGE_DIRS` in `redesign-css-scope.mjs`, else its CSS modules get no layer.
3. Change `executeQuery(query)` to `executeQuery(Astro, query)`.
4. Add `seo` to the `Layout` (it replaces the prototype prop `title`): from the CMS record of the old page when it exists (principle 4), else `overrideSeo([], seoTitle(title), seoDescription(text))`.
5. Delete the old page folder (and its `_sub/` components that nothing else uses).
6. Add the redirects to `astro.config.ts`: the ones of the prototype `astro.config.mjs` for this route, and old route → new route when the path changed. Remove a redirect that the new route makes wrong (for example `/enterprise` → `/enterprise-headless-cms`).
7. In `src/data/navigation.ts`, change the `#` of this route to the real path, and change the links of the old site that point to the old path.
8. A route with parameters must have a `_graphql.ts` (the `routes` integration in `astro.config.ts` expects it).
9. Run the checks. Commit as `Redesign: port <route>`.

## After the port: remove the conversion layer

**Done 2026-10-30, before step 12** (see the log). The prototype is no longer the source (see principle 1), thus this cleanup came before the end of the port. Steps 12 and 13 use the fragment pattern directly. Not done here: `compare` and `case-studies` (the copy of "CMS review → plain text" in `case-studies` stays).

While the port runs, the components of the prototype keep their prototype props (the types of `src/data/*.ts`), thus a change in the prototype is a copy. Each page converts the CMS result into these types in `_sub/buildData.ts` (and in some pages in the frontmatter). When the port from the prototype is finished and the prototype is no longer the source, remove this layer and go back to the simpler form of the old site: each component declares its gql.tada fragment, its props are the fragment types (`FragmentOf<typeof XFragment>`, read with `readFragment`), and the page passes the query result directly.

- Do it one component at a time: give the component a fragment, change its props to the fragment type, and add the fragment to the queries of the pages that use it.
- Delete each `_sub/buildData.ts` when nothing uses it, and the types in `src/data/*.ts` that only the conversion used. The static copy in `src/data/` stays until it moves to the CMS (see "Out of scope").
- The duplicates go too: the three identical `closingQuote` files (`developers`, `media`, `editor-experience`) and the copies of "CMS review → plain text" in `wall-of-love`, `philosophy` and `case-studies`.
- After this step the prototype paths do not need to stay the same (principle 1 ends), and `src/REDESIGN.md` must say that a component gets its data from a fragment.

## Out of scope

- The routes that the prototype marks `todo` (use cases, partners, security, support, `/cms/[slug]`, the landing pages…), the docs, the marketplace, the academy, the user guides, the legal pages. They stay on `LegacyLayout`.
- The CMS models for the static copy in `src/data/`. That is a later phase.
